FIRMWARE SECURITY

      
Secure Bootloader on ARM Cortex-M

      
A bootloader that refuses to run anything it can't verify. Images are checked with ECDSA P-256 over SHA-256 before the jump, and signing happens automatically at build time.

      
  • C
  • mbedTLS
  • ECDSA P-256
  • SHA-256
  • Python

      

        Open image notes ＋
        


reset ─▶ bootloader ─▶ hash(slot A) ─▶ ecdsa_verify(pubkey)
                                     ├─ OK   ─▶ VTOR = app · MSP = app[0] · jump
                                     └─ FAIL ─▶ halt, never boot

          
    
            
  • Fail-safe verification pipeline: nothing executes before the signature check passes.
    • 
            
  • Vector table relocation and MSP set-up for a clean hand-off to the application.
    • 
            
  • Python tooling signs every build, so unsigned images never leave the build step.
    •

BOARD BRING-UP

      
FRDM-MCXA156 LPUART Test

      
Bare-metal MCUXpresso project for NXP's Cortex-M33 MCXA156. It passes data UART ⇄ UART between the mikroBUS and Arduino headers, and UART ⇄ PC through the MCU-Link virtual COM port.

      
  • C
  • MCUXpresso
  • MCXA156
  • LPUART

      

        Open image notes ＋
        


LPUART1 (mikroBUS J5) ──TX──╳──RX── LPUART2 (Arduino J1)
                                │
LPUART0 ◀── MCU-Link VCOM ──▶ PC terminal @ 115200 8N1

          
    
            
  • MCXA pitfalls handled: LPUART_Init() alone isn't enough. The functional clock (FRO12M), the divider and the reset release all have to be set.
    • 
            
  • Input Buffer Enable (IBE) set on every RX pin, otherwise the line is never seen.
    • 
            
  • Overrun recovery: RX is flushed and error flags cleared before each transfer.
    • 
            
  • Loopback self-test at boot, then live per-direction counters.
    •

  • MCXA156
  • ESP32
  • Secure boot
  • OTA
  • Threat modeling
